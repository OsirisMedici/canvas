# Contributing to Canvas community

Thanks for helping shape Canvas. This repository accepts product feedback and documentation improvements. Application development and source code remain private.

## Bugs and feature requests

Search existing issues before opening one. Use the bug form for something that failed; include the edition/version, macOS version, Mac chip, expected result, actual result, and reproducible steps using made-up data. You can report a documentation problem even if you do not have the app.

Use the feature form to describe who needs the change, the job they are trying to finish, the current workaround, and what success would look like. One problem per issue makes follow-up easier. An issue is feedback, not a promise of implementation or a support response time.

## Keep public feedback safe

Do not attach private libraries, databases, personal boards, credentials, private links, or unredacted logs. Prefer a minimal invented example. Check screenshots for names, file paths, source content, and account details before uploading. Share only a short, reviewed diagnostic excerpt when needed. Suspected vulnerabilities belong in [private security reporting](SECURITY.md).

## Documentation pull requests

Small corrections and clearer explanations are welcome. Explain what was confusing and preview the Markdown before submitting. Keep preview status accurate and links working. Do not add application source, installers, copied private notes, software licenses for the app, or unapproved product claims. Screenshots must show verified clean demo content that you have permission to share.

Maintainers review changes before merging. See the [community guidelines](CODE_OF_CONDUCT.md).
